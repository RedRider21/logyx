Perché Logyx

Oggi per il web servono due linguaggi diversi. Logyx cancella quel confine: una sola sintassi, un solo sorgente, deploy semplice come PHP e velocità vicina al C.

🌐

Un sorgente, molti mondi

Lo stesso codice gira nativo sul server e come WASM nel client, senza duplicazione e senza un secondo linguaggio.

⚡

Facile per default, veloce a richiesta

Dinamico e conciso come Python; i tipi si aggiungono solo dove serve prestazione (gradual typing).

🦀

Transpila verso Rust

Da Rust si ereditano nativo, WebAssembly, desktop e mobile — con sicurezza di memoria e ottimizzazioni gratis.

🔒

Il confine è esplicito

I blocchi @start-client mostrano dove passa la rete. Il client non è mai fidato: è anche un confine di sicurezza.

🔌

Interoperabilità dal primo giorno

FFI con C (la lingua franca) e accesso alle crates Rust: l'ecosistema copre i mondi che il linguaggio non gonfia.

🧩

Batterie da web incluse

Routing, template, HTTP e database nella libreria standard, alla PHP. Il cuore del linguaggio resta piccolo.

Che aspetto ha

Sintassi non posizionale con graffe, punto e virgola opzionale, tipi facoltativi. Server fuori, client dentro le isole.

// server (come PHP) + isola client → WASM
route "/" {
    saluto = "Ciao, mondo!"

    render <html><body>
      <h1>{saluto}</h1>
      <button id="btn">Cliccami</button>
      <p id="out">—</p>

      @start-client
        clic = 0
        on "click" of "#btn" {
            clic = clic + 1
            set text of "#out" to "Premuto {clic} volte"
        }
      @end-client
    </body></html>
}
// sottoinsieme tipizzato → compila a nativo via Rust
fn fib(n: int) {        // ritorno dedotto
    if n < 2 {
        return n
    }
    return fib(n - 1) + fib(n - 2)
}

fn main() {
    for i in range(11) {
        print("fib({i}) = {fib(i)}")
    }
}

// $ python3 main.py build native_fib.logyx
// → genera Rust e compila a eseguibile

A che punto è

Logyx è un prototipo funzionante in Python (lexer, parser, interprete, render web, transpiler Rust). Ecco la mappa.

Siamo alla versione 0.

Il prototipo in Python e la transpilazione verso Rust sono impalcature temporanee per far nascere il linguaggio. L'obiettivo è un Logyx self-hosted — un compilatore scritto in Logyx che genera direttamente codice macchina — in cui né Python né Rust resteranno una dipendenza.

✅
Nucleo del linguaggioVariabili, funzioni, if/while/for, liste e mappe, stringhe con interpolazione, builtin.
✅
Web lato serverroute + render con interpolazione, escaping e blocchi { for } / { if }.
✅
Isole client → JavaScriptBlocchi @start-client compilati a JS: eventi, stato, aggiornamento del DOM.
🟡
Transpiler Rust (sottoinsieme tipizzato)Aritmetica, stringhe, controllo di flusso, funzioni con inferenza dei tipi, liste e mappe, moduli e gestione errori (→ Result).
✅
Compilatore in Rust (Fase 1 del bootstrap)logyxc: lexer, parser, inferenza dei tipi e backend in Rust, verificato conforme al prototipo su tutti gli esempi.
⏳
Prossimo traguardo: self-hostingRiscrivere il compilatore in Logyx stesso, così da non dipendere più né da Python né da Rust.

Come iniziare

Il prototipo gira con il solo Python 3.8+ (nessuna dipendenza). Rust serve solo, in opzione, per compilare a nativo.

git clone https://github.com/RedRider21/logyx.git
cd logyx/prototype

# esegui un programma
python3 main.py ../examples/hello.logyx

# avvia un server web
python3 main.py serve ../examples/web_demo.logyx 8137

# transpila a Rust e compila a nativo
python3 main.py build ../examples/native_fib.logyx
